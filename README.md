# VIP Chat Analyzer

MVP для VIP-менеджера, тимлида и руководителя VIP-отдела: разбирает переписки с игроками, оценивает качество коммуникации, эмоциональную динамику, нарушения и приоритет обращения, со ссылками на конкретные сообщения. Данные загружает пользователь (`dialogs.json` и `players.csv` из тестового задания). В репозиторий они не включены: после запуска выберите оба файла кнопками «Выбрать файл диалогов» и «Выбрать файл игроков» и нажмите «Загрузить данные».

## Запуск

Python 3.10+.

```
pip install -r requirements.txt
python -m uvicorn app.main:app --port 8000
```

Откройте http://localhost:8000. Ключи AI вводятся в разделе **Настройки** (Google Gemini по умолчанию, Anthropic дополнительно).

## Разделы

- **Анализ чатов**: два режима.
  - *AI-анализ*: загрузить `dialogs.json` и `players.csv` (без загрузки анализировать нечего), выбрать провайдера в Настройках, нажать «Анализировать все». Перед запуском показываются модель, объём и приблизительная стоимость, запуск только после подтверждения. Если часть диалогов уже проанализирована, окно сообщает об этом: без галочки «Проанализировать заново» для них остаются прежние результаты, с галочкой они пересчитываются.
  - *Импорт анализа*: загрузить готовый `analysis_results.json`, подготовленный в Claude Code. Запросов к AI нет. Инструкция: `docs/CLAUDE_CODE_ANALYSIS_GUIDE.md`, схема: `schema/analysis_results.schema.json`, пример: `docs/analysis_results.example.json`.
  - После каждого анализа или импорта в `results/` автоматически создаётся файл `analysis_ГГГГ-ММ-ДД_ЧЧ-ММ-СС.json` (старые не перезаписываются и не удаляются). Его можно открыть обратно через «Импорт анализа».
  - Браузер запоминает последний открытый анализ и интерфейс (localStorage), при повторном открытии результаты показываются без запросов к AI. Очистка localStorage даёт пустой Dashboard, серверный кэш и файлы остаются. Вернуть результаты: «Анализировать все» (готовые результаты подхватятся без запросов к AI) или импорт файла.
- **Правила анализа**: редактор регламентов по категориям, добавление и отключение своих правил, версии (`v1`, `v2`, ...) с восстановлением. Новые правила применяются к следующему анализу без перезапуска. Изменение правил ничего не пересчитывает: прежние результаты получают отметку «Правила изменены».
- **Настройки**: ключи, модели, проверка подключения, активный провайдер.

## Как устроено

- `rules/evaluation_rules.md`: активные правила (версии в `rules/versions/`). `rules/safety_baseline.md`: обязательные меры безопасности, добавляются к любым правилам.
- `app/metrics.py`: детерминированные метрики и флаги из данных.
- `app/schemas.py`: единая схема результата для обоих режимов.
- `app/analyzer.py`, `app/providers/`: один запрос на диалог, структурированный JSON, одинаковые правила для Gemini и Anthropic.
- `app/guardrails.py`: ссылки на сообщения, краткость, объединение дублей, запрет коммерческих рекомендаций при сигналах безопасности, приоритет.
- `app/cache.py`: результаты `cache/analysis.json` (источник, модель, версия правил). Результат помечается устаревшим при смене модели, правил или содержимого диалога. Результаты старого формата сохраняются в `legacy_v1`.
- `static/`: интерфейс (vanilla JS, Chart.js).

Оценки эмоций и вовлечённости приблизительные, это интерпретация модели, а не измерение состояния.

## Тесты

```
python -m pytest
```

Тесты используют моки и не обращаются к AI API. Живая проверка правил на D003, D006, D008, D010, D011 (платные запросы, только по явной команде): `python -m scripts.regression_check --confirm`.

Схему результата можно обновить командой `python -m scripts.export_schema`.
